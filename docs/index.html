How it works

From a Mac mini boot to a deployed app — everything automated.

01

Boot the VM

A LaunchDaemon starts Lima (QEMU, Ubuntu 24.04) at system boot — no login required. k3s comes up automatically. One command provisions the whole cluster.

infra cluster setup
02

Bootstrap GitOps

Build and push the CI runner and GitOps controller images, deploy the in-cluster registry, run the mesh invite/join dance, and push the GitOps repo into the mesh network.

infra cluster bootstrap
03

Push code, watch it ship

The mesh-gitops-controller polls your platform repo every 30 seconds. The apps-controller polls your app repo. Commit a manifest change and it's live within half a minute — no webhooks, no external CI service.

git push origin main
# → applied in <30s
04

Chat with your agent

The Claude Code agent pod runs in your cluster with persistent workspace storage and full Git access over the mesh. Send it a task in chat, get code back. Your team sees everything in the same thread.

@agent refactor the auth module
         and open a PR

Secure by design, not by policy

  • ✓
    Push scoping in CI — each pipeline can only push images whose name matches its repo. Enforced by a session-gated registry proxy, not trust.
  • ✓
    BuildKit mTLS — arbitrary code inside the CI pod cannot connect to BuildKit without the client certificate generated at pod startup.
  • ✓
    Two-tier RBAC — the GitOps controller has ClusterRole access; the apps controller is scoped to its namespace only.
  • ✓
    No SSH keys — Git access goes through the P2P mesh authenticated by pubkey exchange, not stored credentials.
  • ✓
    Pod Security policies — baseline enforcement on default namespace, restricted for infrastructure workloads.
